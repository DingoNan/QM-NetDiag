## 一、愿景与目标用户

### 1.1 一句话定位

> **v1 是给运维人员用的「工业 CT 机」，v2 是给普通人用的「智能手表」。**

| 维度 | v1（当前） | v2（本次） |
|---|---|---|
| **目标用户** | 政企内网 IT 运维、信创集成商 | 游戏玩家、视频博主、远程办公、跨境电商、普通网民 |
| **使用场景** | 排查专线故障、做合规报告 | 看游戏卡不卡、视频加载快不快、节点通不通 |
| **典型问题** | "信创环境下一体化系统到某节点的丢包率是多少？" | "我家宽带到腾讯服务器延迟多少？" |
| **审美取向** | 政务蓝、表格密集、严肃 | 暗色 + 霓虹、图形化、酷炫 |
| **上手成本** | 需要懂网络术语 | 选个图标，点一下 |
| **结果呈现** | HTML 报告（合规存档） | 仪表盘 + 可分享卡片 |

### 1.2 目标用户画像

| Persona | 典型场景 | 核心诉求 |
|---|---|---|
| **游戏玩家"小张"** | 玩 LOL/原神/Steam，看延迟能不能上分 | "到腾讯/Steam 的延迟稳不稳，够不够打排位" |
| **视频博主"小李"** | 录 4K 视频上传 B站 | "现在上传速度够不够，能不能赶在中午发" |
| **远程办公"小王"** | 海外办公，连 Zoom/Slack | "今天到海外的链路是不是正常" |
| **跨境电商"小陈"** | 常登 Google/ChatGPT/亚马逊 | "科学上网节点还活着吗，访问快不快" |
| **开发者"小赵"** | 频繁 GitHub clone/push | "GitHub 现在能不能拉代码，慢不慢" |

五类用户共享一个底层诉求：**用一个按钮，替代"看不懂的输出"和"说不清的体感"**。工具的价值锚点不是测速数据本身，而是把数据翻译成"我该不该换网络 / 该不该报修 / 是不是节点问题"的结论。

## 二、市场与竞品分析

个人网络测试赛道已有成熟玩家，v2 不打算在"单一测速"上硬碰硬，而是占据"场景化多目标诊断"的空白。

| 产品 | 强项 | 短板 | 对 v2 的启示 |
|---|---|---|---|
| **Speedtest by Ookla** | 测速准、品牌强、全球节点 | 只测"到最近节点"的带宽，不回答"到腾讯/Steam 快不快" | 带宽测速做到不输它即可，不追求超越 |
| **Fast.com（Netflix）** | 极简，打开即测 | 只测下行，无诊断、无多目标 | 验证"零学习成本"是可行的 |
| **网速管家** | 国内场景、带工具箱 | 界面广告重、功能杂 | 提示 v2 保持纯净，拒绝广告堆砌 |
| **Steam 内置测速** | 精准反映游戏下载体验 | 只覆盖 Steam 自家 | 游戏场景的"单点深度"值得学 |
| **Cloudflare Speed** | 准、无广告 | 偏技术向 | 技术用户可接受的克制风格 |

**v2 的差异化定位**：`场景化目标库 × 多目标并行 × 图形化诊断 × 可分享卡片`。竞品要么只测带宽（Speedtest/Fast），要么只测单目标（Steam），没有一个工具能回答"我常玩的游戏、常看的视频、常上的网站，现在整体什么状况"。这正是一键全测的价值。

## 三、设计原则

五条原则贯穿所有页面与交互，评审时以它们为标尺：

1. **用户只问"卡不卡"**：任何页面不出现未经翻译的原始指标，先给结论（流畅/一般/卡顿），再给数据。
2. **图形优先于文字**：速度计、雷达图、波形图承载结论，表格只做补充。
3. **本地优先、零追踪**：默认不上传任何数据，历史记录只存在本机，不收集用户标识。
4. **即开即用、零配置**：首次启动即可完成一次完整测试，设置项全部有默认值。
5. **结果可行动**：每个结论附带一条行动建议（重启路由器 / 检查节点 / 联系运营商）。

## 四、核心体验流程

### 4.1 首次启动旅程（目标：60 秒内完成第一次测试）

```
启动 → 看到霓虹 Logo 与"开始测试" → 默认全测（自动选 5 个热门目标）
    → 实时进度与波形 → 结果页展示综合评分 + 分类卡片 → 引导分享
```

首次启动不弹设置、不引导登录、不要求填任何东西。唯一的可选项是"选择你常用的场景"（游戏/视频/办公/开发/海外），选完后自动生成快捷目标栏。

### 4.2 日常使用旅程

```
打开 → 快捷目标栏一键复测（常驻 3-5 个目标）
    → 30 秒内出结果 → 对比上次 → 正常则关闭，异常则看建议
```

日常路径要短于 30 秒：启动即恢复上次的快捷目标，主按钮位置固定，结果页"再测一次"与"分享"并列。

### 4.3 分享回流旅程

```
结果页 → 生成海报 → 发到群/朋友圈 → 好友扫码 → 打开即测 → 回流
```

海报二维码指向"重测入口"，不指向个人主页、不收集扫码者信息。分享是获客主渠道，回流路径必须一步到位。

## 五、核心功能设计

### 5.1 特性 A：预置网站库（即开即用）

**数据结构**（比 v1 稿增加 `suggested_test` 与 `fallback` 字段，解决失效与降级）：

PRESET_TARGETS = [

        "name": "腾讯·英雄联盟",
        "category": "game",
        "icon": "game",
        "host": "lobby.na1.lol.pvp.net",
        "port": 2099,
        "test_type": ["ping", "tcp"],
        "region": "domestic",
        "weight": 95,

**分类与数量规划**（图标统一走内嵌 SVG，不依赖 emoji 字体）：

| 分类 | 数量 | 示例 |
|---|---|---|
| 游戏 | 25 | LOL/DOTA2/CS2/原神/王者/Steam/Epic/暴雪/Riot/PSN |
| 视频 | 20 | B站/优酷/爱奇艺/腾讯视频/YouTube/Netflix/Twitch |
| 通讯 | 15 | 微信/QQ/钉钉/企微/Discord/Telegram/Zoom/Teams/Slack |
| 开发 | 15 | GitHub/GitLab/npm/PyPI/Stack Overflow/ChatGPT |
| 社交 | 10 | 微博/知乎/小红书/Twitter/Instagram |

| 海外 | 12 | Google/Cloudflare/AWS/Azure/Apple/Microsoft |

**失效与更新机制**：
- 每个目标标注 `data_updated` 日期，超过 90 天未验证的在列表打"可能失效"角标。
- 单目标失败时自动尝试 `fallback`，仍失败则标黄并提示"目标可能变更"，不标红吓用户。
- 预置库随版本发布更新，v2 首版不做云端热更新（本地 JSON 即可，避免隐私与合规负担）。

### 5.2 特性 B：可视化诊断（图形化）

四个可视化组件是 v2 的脸面，组件规范见 6.4：

| 组件 | 用途 | 交互 |
|---|---|---|
| 速度计 Gauge | 单目标延迟/评级的核心呈现 | 指针平滑转动，数字滚动 |
| 雷达图 Radar | 多目标对比（延迟/带宽/稳定性） | 逐项点亮，末端数值标签 |
| 波形图 Waveform | 测试过程实时延迟曲线 | 边测边画，抖动区域着色 |
| 健康度环 ScoreRing | 综合评分 A+/A/B/C/D | 环形进度 + 渐变描边 |

### 5.3 特性 C：分享卡片（社交属性）

**海报规格**：
- 竖版 `1080×1920`（朋友圈/抖音）与方版 `1080×1080`（微信群）两套模板。
- 顶部：Logo + 综合评分大数字；中部：雷达图 + 分类明细；底部：测试时间 + 二维码。
- 二维码载荷为"重测入口"短链或本地生成的重测数据（见隐私边界）。

**隐私边界**：海报**不包含**本机 IP、MAC、机器名、运营商账号信息。默认只呈现评分、延迟区间、目标名称与时间。用户可勾选"显示公网 IP 与运营商"（P1 功能）后手动导出。

### 5.4 特性 D：评分系统（分层设计）

v1 稿的评分只覆盖延迟/抖动/丢包，v2 补充**带宽维度**与**场景加权**，让"游戏 35ms 但带宽低"这类情况得到合理评价。

**单目标健康度评分**（0-100）：

```python
def score_single(metrics: dict) -> tuple:
    latency = metrics.get("avg_latency_ms", 999)
    jitter  = metrics.get("jitter_ms", 0)
    loss    = metrics.get("loss_pct", 100)
    bw_mbps = metrics.get("bandwidth_mbps", None)

    latency_score = max(0, 100 - latency * 1.2)      # 100ms 归零
    jitter_score  = max(0, 100 - jitter * 6)
    loss_score    = max(0, 100 - loss * 12)
    bw_score      = 100 if bw_mbps is None else min(100, bw_mbps * 2)  # 50Mbps 满分

    # 默认权重：延迟 45% 抖动 20% 丢包 20% 带宽 15%
    score = (latency_score * 0.45 + jitter_score * 0.20
             + loss_score * 0.20 + bw_score * 0.15)

    grade, label = _grade(score)
    return (score, grade, label)
```

**场景加权**：不同场景对指标敏感度不同，评分时按用户选择的场景调整权重。

| 场景 | 延迟权重 | 抖动权重 | 丢包权重 | 带宽权重 |
|---|---|---|---|---|
| 游戏 | 0.55 | 0.25 | 0.20 | 0.00 |
| 视频/上传 | 0.10 | 0.05 | 0.10 | 0.75 |
| 办公/会议 | 0.35 | 0.25 | 0.25 | 0.15 |
| 通用 | 0.45 | 0.20 | 0.20 | 0.15 |

**综合评分**：一键全测后，取所有目标单目标分的加权平均，权重由用户常用场景决定，生成 `A+/A/B/C/D` 与一句总评（"整体流畅，游戏场景优秀；上传偏慢建议查运营商"）。

### 5.5 特性 E：收藏夹与自定义目标

- 收藏夹：常用目标置顶，最多 5 个，构成"快捷目标栏"。
- 自定义目标：P0 提供"主机名/端口 + 测试类型"的极简表单（普通用户版本），P1 提供高级表单（Ping 次数、带宽时长）。
- 自定义目标同样参与评分与历史记录，但海报默认不打自定义目标标签，避免暴露个人业务信息。

### 5.6 特性 F：历史趋势（30 天）

- 存储：本机 `history/` 目录下按周分文件的 JSON（轻量、可删可备份），不做 SQLite（单机数据量小，JSON 更透明）。
- 趋势页：30 天延迟/带宽曲线，标注"较上次"变化百分比，支持按目标筛选。
- 隐私：历史数据不上传；提供"清空历史"一键入口。

### 5.7 特性 G：成就系统（P1，防刷设计）

| 成就 | 触发条件 | 防刷约束 |
|---|---|---|
| 首次出发 | 完成第 1 次测试 | 无 |
| 十测老手 | 累计 10 次测试 | 同一目标 5 分钟内重复不计 |
| 深夜测网人 | 任意 3 天在 23:00-05:00 完成测试 | 每天最多计 1 次 |
| 节点医生 | 累计 20 次海外目标测试 | 失败与超时同样计（鼓励诊断） |
| 全网通 | 单次测试覆盖 5 个以上分类 | 需一键全测触发 |

成就数据本地存储，不联网排名（P2 再评估好友对比）。

### 5.8 特性 H：公网 IP 与 Wi-Fi 信息（P1）

- 公网 IP + 归属地 + 运营商：调用本机 socket 连接目标后从对端信息推断；不依赖第三方 IP 查询接口（避免隐私泄露与接口不稳定）。
- Wi-Fi 信号：读取系统 Wi-Fi RSSI（Windows 用 `netsh wlan show interfaces`），显示"强/中/弱"等级与建议（"离路由器近一点或换 5G 频段"）。

### 5.9 明确不做

| 不做 | 原因 |
|---|---|
| iperf3 服务端配置 | 面向运维，个人用户无此需求 |
| 长期监测/定时检测 | 个人场景用"历史趋势"替代，持续监测对普通用户是打扰 |
| PDF/HTML 报告导出 | 用海报替代；需要详细日志的保留 TXT 导出（P2） |
| 多用户/角色权限 | 单机单用户 |
| 端口扫描/漏洞探测 | 防止工具被误用为黑客工具，只做连通性测试 |

### 6.1 设计语言

暗色优先 + 霓虹强调 + 大留白 + 图形优先。所有状态用颜色 + 形状双重表达（不只靠颜色区分，兼顾色弱用户）。

### 6.4 组件规范

**速度计 Gauge**：
- 半圆 180° 表盘，刻度从 0 到 300ms（对数刻度：0-50ms 占 60% 弧长，突出低延迟差异）。
- 指针动画 600ms ease-out；数值用 JetBrains Mono 48px。
- 颜色：`<30ms` 绿，`<80ms` 青，`<150ms` 黄，`>=150ms` 红。

**健康度环 ScoreRing**：
- 环形 SVG 描边，渐变 `accent-gradient`，进度动画 800ms。
- 中心 A+/A/B/C/D 大字母 + 下方评语。

**目标卡片**：
- 圆角 `--radius-lg`（16px），背景 `--bg-elevated`，边框 `--surface-line`。
- 状态角标：绿点"流畅" / 黄点"一般" / 红点"卡顿"，带横向微动画。

**主按钮**：
- 渐变背景 + `--glow-primary` 光晕，hover 光晕增强，active `scale(0.97)`。

### 6.5 微交互清单

- 按钮 hover：发光增强 + 轻微上浮。
- 数字滚动：0 到目标值 800ms cubic-bezier 动画。
- 测试进度：环形进度 + 实时百分比 + 当前项高亮。
- 加载骨架屏：页面切换时组件级骨架，不做全屏白屏。
- 波形图：边测边画，超出容器自动滚动。
- 主题切换：瞬时切换（不做全局过渡动画，避免卡顿）。

### 6.6 无障碍

- 状态不只靠颜色：绿/黄/红同时配合"流畅/一般/卡顿"文字与图标。
- 对比度：正文文本与背景对比度 ≥ 4.5:1。
- 支持 `prefers-reduced-motion`：关闭指针/数字动画。
- 窗口最小尺寸 960×640，支持字体缩放 125%。

### 8.2 关键技术决策

**tkinter 能否支撑霓虹 UI？** 这是 v2 最大的工程风险，结论与方案：

- tkinter 原生控件不支持圆角、渐变、发光、半透明。**决定：全部自定义组件用 Canvas 自绘**——v1 已积累 HTML 原型经验，Canvas 可完全复刻（速度计、雷达图、波形、圆角卡片均可用 Canvas 画出来）。
- 字体与渲染：Canvas `create_text` 支持 TTF，思源黑体与 JetBrains Mono 打包进资源目录（约 15MB，可接受）。
- 动画：用 `after()` 定时器驱动，动画帧率控制在 30fps（Canvas 重绘成本可接受）。
- 若 Phase 1 评估 Canvas 性能不足（缩放时模糊、复杂波形卡顿），备选方案为 **pywebview 嵌入 HTML 仪表盘**（保留本地运行、零上传的隐私承诺），切换成本在 UI 层封装后可控。

**并行测试调度**：
- `concurrent.futures.ThreadPoolExecutor(max_workers=4)`，每项测试独立超时（5 秒上限）。
- 结果通过 `queue` 回传 UI，单项完成即刷新，不阻塞其他项。
- 用户点"停止"：置位停止事件，1 秒内强制结束子进程（复用 v1 `run_cmd` 的 stop_event 机制）。

**数据存储**：
- 配置：`config.ini`（复用 v1）。
- 历史：`history/YYYY-Wxx.json` 按周分文件，单文件 ≤ 200 条，30 天自动归档清理。
- 收藏与成就：`user_data.json` 单文件。
- 全部 UTF-8，全部本地。

**海报生成**：
- `qrcode` 库生成二维码（Pillow 已随打包存在）。
- 海报用 Pillow 绘制：中文字体必须显式指定思源黑体 TTF，否则 Windows 下乱码。
- 两套模板（1080×1920 / 1080×1080），模板用 JSON 描述布局，后续改版不动代码。

### 8.3 新增依赖

- `qrcode`（约 5KB）—— 二维码。
- `Pillow` —— 海报 PNG 生成（部分平台 PyInstaller 已内置，需确认打包配置）。
- 不引入 matplotlib / pywebview / SQLite（P2 若上 pywebview 再评估）。

## 九、隐私与合规设计

个人用户比政企用户对"采集"更敏感，隐私是 v2 的信任底座：

| 数据 | 处理方式 |
|---|---|
| 测试目标与结果 | 仅本地展示与存储，不上传 |
| 历史记录 | 本地 `history/`，提供一键清空 |
| 本机 IP/MAC/机器名 | 仅用于测试绑定源 IP，不写入海报、不展示 |
| 用户标识/埋点 | 无 SDK、无统计代码、无崩溃上报 |
| 第三方 IP 查询接口 | 不调用（避免泄露本机 IP 给第三方） |

合规要点：
- 海报二维码只编码"重测数据摘要 + 版本号"，不包含任何个人信息，离线可生成。
- 自定义目标的海报默认不打目标标签，用户手动开启后才显示。
- README 与设置页同时声明"纯本地、零上传"，与 v1 保持一致的口径。

## 十、实施路线图

### Phase 1：MVP（4 周）—— 跑通"选目标 → 测 → 看分"

**目标**：完成一次完整的一键全测并展示评分，作为可评审的里程碑。

| 周次 | 交付 | 验收标准 |
|---|---|---|
| 第 1 周 | 配色/字体 token 重构；Canvas 基础组件（卡片/按钮/进度） | 三页布局可切换，暗色主题生效 |
| 第 2 周 | `presets/targets.py` 首批 30 目标；一键全测调度 | 5 目标并行测试 ≤ 25 秒 |
| 第 3 周 | Gauge / Radar / Waveform 组件 | 测试过程实时出图，30fps 不卡 |
| 第 4 周 | 评分算法 + 结果页 | 单目标与综合评分正确，评语可解释 |

**验收**：10 名内测用户中 8 名能在 60 秒内完成首次测试并理解结果。

### Phase 2：完善（4 周）—— 体验闭环

- 完整 100+ 预置目标库（含 fallback 与失效标记）。
- 历史趋势页 + 按周 JSON 存储。
- 收藏夹与快捷目标栏。
- 主题切换（暗/亮/跟随系统）。
- 成就系统 v1（首批 5 个成就）。

**验收**：日常复测路径 ≤ 30 秒；历史页 30 天数据可正确聚合。

### Phase 3：发布（2 周）—— 分享与打磨

- 分享海报两套模板（Pillow + 二维码）。
- 复制摘要（纯文本，兼容微信）。
- 性能优化（启动 < 2s，内存 < 150MB）。
- 打包：Windows 单绿色包（x64 优先），麒麟/macOS 沿用 v1 脚本。
- 官网/仓库更新 + 使用文档。

**验收**：海报在微信群/朋友圈打开无乱码、二维码可重测；Windows Defender 无拦截。

## 十二、风险与应对

| 风险 | 应对 |
|---|---|
| tkinter Canvas 做霓虹 UI 性能不足 | 30fps 帧率上限；备选 pywebview 方案（8.2） |
| 预置网站域名/IP 变动 | fallback + 90 天失效标记 + 随版本更新 |
| 海外目标超时被误判"网络差" | 海外目标超时标黄"可能受限"，不标红 |
| 用户误以为能测"自己服务器" | 自定义目标入口保留，高级参数折叠在 P1 |
| 工具被误用为扫描器 | 只做连通性（ping/tcp/dns/http），不做端口扫描 |
| 评分被质疑"不准" | 算法开源、指标透明，结果页可展开原始数据 |
| 美工能力受限 | 设计 token + 参照成熟组件库（6.1），避免从零设计 |

## 十三、开源与可持续

v2 定位开源免费，个人开发者需要考虑长期维护的可持续性：

- **开源协议**：建议 MIT（个人工具，最大限度降低使用者顾虑）。
- **捐赠入口**：官网/仓库放低调的赞助链接与二维码（对应现有官网"打赏弹窗"设计），不内嵌在应用内打扰。
- **可选增值**（P2 评估，保持克制）：高级自定义目标数量、海报去水印、批量测试导出，作为"赞助档位"而非强制付费。
- **社区反馈**：GitHub Issues 作为需求入口，README 提供模板（目标失效报告、新增目标建议）。
